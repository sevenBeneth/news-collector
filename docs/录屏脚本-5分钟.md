## 二、分镜与台词（照读即可）

### 开场（全屏：信息架构思维导图）

> 大家好，我的作品是**芜湖市科技创新新闻收集平台**：面向芜湖本地，自动采集政府和媒体的科技信息，再用 DeepSeek 生成摘要。屏幕上是产品信息架构。

### 目标用户（切到首页）

> 目标用户四类：**本地科技型企业从业者**最关心科技政策和高企、创新券申报；**高校师生和科研人员**关注创新平台与成果转化；**科技管理部门**要快速掌握全市动态；**招商和园区人员**关注企业创新与项目进展。

### 解决的问题（首页缓慢下滑）

> 要解决三个问题。**一是信息分散**，科技信息散在科技局、政府门户、芜湖新闻网等多个渠道，人工翻找费时；**二是时效性强**，高企认定、创新券兑付错过窗口就要再等一年；**三是阅读成本高**，单篇篇幅长，通勤时很难读完。

### 创新点（切回首页 AI 摘要预览）

> **业务创新**三点：一是**本地化一站式聚合**，把芜湖官方科技信息源按八个频道重组；二是 **AI 三十秒速读**，每条自动生成摘要和关键词；三是**采集、审核、发布闭环**，内容先进待审队列，审核通过才发布。
>
> **技术创新**三点：一是**多源采集加双键去重**，用原文链接和标题哈希避免重复入库；二是**大模型结构化输出**，固定提示词让 DeepSeek 直接返回 JSON，失败时自动降级为本地抽取式摘要；三是**编码归一与正文抽取**，政府站点编码不统一，采集器做编码归一并剥离导航广告。

### 采集器（切到终端，跑一次采集）

> 先看数据从哪来。一条命令启动采集器，读取后端下发的采集源配置，依次抓取科技局四个频道、市政府 RSS、市政府新闻中心和芜湖新闻网。这一轮解析 127 条、新增 112 条，重复的自动跳过，入库后异步生成摘要。

### 首页（切到 H5 首页）

> 回到小程序。首页轮播图不是贴图，而是**由数据库标题自动生成**：脚本读取关联新闻的真实标题，自动折行、字号自适应、按频道配色，比例与滑动框一致，铺满不变形。下面是八个频道，信息流显示标题、封面、**AI 摘要前 40 字**、来源和时间。

### 详情页 + AI 实时生成（点开一条新闻，等动画走完）

> 点开一条新闻。标题下面是来源和时间，再往下是重点：**AI 摘要卡片是真的在实时生成**——未生成时显示骨架屏和生成中动效，前端每 1.2 秒轮询摘要状态接口；拿到结果后**逐字打字机输出**，进度条同步增长，最后关键词逐个渐入。在管理端点一下"重新生成摘要"，手机上两三秒就能看到完整过程。往下是正文，底部可跳原文，并有点赞、收藏和评论。

### 管理端（切到管理端）

> 管理端内置在 Spring Boot 里。**看板**显示新闻总数、待审、已发布与 AI 摘要成败数；**新闻管理**可按状态和频道筛选，点通过即发布、点驳回即下架，还能重新生成或批量补齐摘要；另有轮播、采集源、采集日志和用户管理。

### 插件与组件来源（可叠一张清单图）

> 说明第三方资产：前端基于 DCloud 插件市场的**资讯模板**，插件 id 1988；富文本用 **Parser**，id 805；上拉加载用 **mescroll**；UI 用 **uni-ui** 的卡片、弹窗、图标等组件；图标字体用 iconfont。**本项目未使用 colorUI**。自研组件三个：轮播、AI 摘要卡片、关键词标签。后端 Spring Boot 加 MyBatis，第三方服务 DeepSeek，管理端零依赖。

### 源代码目录结构（切到编辑器）

> 源码分四块：**api-server** 是后端，含用户端、采集端、管理端接口与业务、AI 摘要、采集入库服务，资源目录是配置、MyBatis 映射和内置管理页；**crawler** 是采集器，含站点适配器、正文抽取和主流程；**web** 是前端，config 下的 api.js 是唯一要改的接口配置；**sql** 是建表与初始化数据，**docs** 是接口契约与信息架构。

## 四、现场可能被问到的问题（备答）

| 问题 | 回答要点 |
|---|---|
| **为什么不用 colorUI？** | 本项目 UI 以 uni-ui 组件加自定义样式为主；colorUI 是整套色彩与组件体系，与既有模板风格冲突、改造收益低，故未引入。 |
| **哪些是模板自带的，哪些是你写的？** | 模板提供页面骨架、样式体系与部分组件（Parser / mescroll / uni-ui / iconfont）；我重写了新闻域数据结构、接口、多源采集器、AI 摘要链路、管理端与 3 个自研组件。比例见 `docs/插件与来源说明.md`。 |
| **AI 摘要是真调用还是写死的？** | 真实调用 DeepSeek `deepseek-chat`；`ai_log` 表记录每次请求的 prompt / completion / total tokens 与耗时，单条约 300 tokens。 |
| **大模型算不算"云"？** | 作业允许"云服务器**或**第三方后端"，本项目用第三方 DeepSeek API 承担 AI 能力；用户管理与 Banner 由 MySQL 表承担；上云方案写在 README 的后续规划。 |
| **云数据导出在哪？** | `tools/make-release.cmd` 一键产出源码压缩包与 `news_collector_dump_*.sql` 数据库导出。 |
| **采集合规吗？** | 四个源均无 robots 限制；采集器限速 0.8–1.8 秒、单线程、失败退避；只存标题/正文/来源/原文链接，页面标注来源并可跳原文，仅用于课程演示。 |
